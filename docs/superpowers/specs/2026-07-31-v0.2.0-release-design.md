# v0.2.0 Release Design

## Goal

Publish the merged data-foundation work as GitHub Release `v0.2.0` and NPM
package `tr-iban@0.2.0`, with every public document and visual surface describing
the same four data formats and version.

## Scope

- Update repository and package versions to `0.2.0`.
- Close the current changelog entry as `0.2.0` dated `2026-07-31`.
- Keep the seven existing public API functions and all 70 institution records
  unchanged.
- Update README, package README, release guidance, launch copy, and Figma launch
  assets from the old `v0.1.1`/three-format message to `v0.2.0` with JSON, CSV,
  SQL and SQLite.
- Publish reproducible release assets, checksums, SBOM and NPM tarball.
- Run the scheduled official-source check once after publication.

## Out Of Scope

- New IBAN behavior or institution records.
- PHP, Python, Go, Rust or .NET packages in this repository.
- A new visual identity or unrelated promotional site.

## Release Flow

1. Change version metadata and public copy on a release branch.
2. Update only the stale text in the existing Figma visual system, export the
   affected PNG assets, and verify their dimensions and legibility.
3. Run live-source review and the complete offline quality suite.
4. Merge through a pull request after GitHub checks pass.
5. Create signed-off tag `v0.2.0`; the tag workflow builds and publishes GitHub
   assets only after verification succeeds.
6. Dispatch trusted NPM publishing only after the GitHub Release exists and its
   tag points to the same commit.
7. Install from NPM in a clean temporary consumer and verify release checksums.

## Failure Handling

- A TCMB source diff blocks publication and requires human data review.
- A CI, checksum, tag/version, GitHub Release or NPM verification failure stops
  the next publication stage.
- Published assets are never replaced silently; a defect is corrected in a new
  Semantic Versioning release.

## Public Surface Contract

README, package README, CHANGELOG, release documentation, launch copy, Figma
assets, package metadata and generated release assets must agree on version
`0.2.0`. The Divan attribution remains linked and Divan remains a design and
development tool, not a runtime dependency.

## Acceptance Criteria

- Local full verification and remote Node 22/24 CI pass.
- GitHub Release `v0.2.0` includes every documented asset and valid checksums.
- NPM reports `tr-iban@0.2.0` as `latest` with provenance/trusted publishing.
- A clean consumer can import the package and identify a synthetic IBAN.
- Scheduled source check completes without changing canonical data.
- Repository `main` is clean and synchronized with `origin/main`.
