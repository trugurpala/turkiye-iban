# v0.2.2 Patch Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Publish the merged audit-hardening work as a verified `v0.2.2` GitHub Release and `tr-iban@0.2.2` NPM package.

**Architecture:** The canonical institution source and generated data remain unchanged. A release-only branch updates all SemVer and public-release surfaces, is merged through required CI, then tags the exact current `main` commit so the existing release and trusted-publishing workflows produce immutable artifacts.

**Tech Stack:** npm workspaces, TypeScript, Python 3.12+, GitHub Actions, GitHub Releases, NPM OIDC trusted publishing.

## Global Constraints

- Release version is exactly `0.2.2`; tag is exactly `v0.2.2`.
- No provider record, schema, fixture, public API, or runtime dependency changes.
- GitHub Release must precede the NPM trusted-publishing workflow.
- Do not claim NPM publication until the registry reports `tr-iban@0.2.2`.

---

### Task 1: Prepare release surfaces

**Files:** `package.json`, `package-lock.json`, `packages/typescript/package.json`, `CHANGELOG.md`, `README.md`, `docs/PACKAGE_INDEX_PUBLICATION.md`.

- [ ] Set root and workspace package versions to `0.2.2` without creating a local tag.
- [ ] Move the audit-hardening entries into a dated `[0.2.2]` changelog section and update comparison links.
- [ ] Point the README direct tarball example and package-index status at `v0.2.2`.
- [ ] Run `git diff --check` and verify no canonical data file is changed.

### Task 2: Verify the release candidate

**Files:** generated data and temporary ignored `release-artifacts/`.

- [ ] Install locked Node dependencies and Python tooling.
- [ ] Run `npm run data:check-remote`, `npm test`, `npm pack --workspace packages/typescript --dry-run`, `npm audit --json`, and `python -m pip_audit -r tools/requirements.txt`.
- [ ] Build a local `v0.2.2` release-artifact directory and verify `SHA256SUMS`.
- [ ] Confirm generated drift is empty and all release assets are listed.

### Task 3: Merge the release preparation

**Files:** all Task 1 files.

- [ ] Commit only the release-preparation change with `release: prepare v0.2.2`.
- [ ] Push `codex/v0.2.2-release`, open a PR, and wait for required Node 22, Node 24, and data-validation checks.
- [ ] Merge only after all required checks report success.

### Task 4: Publish and verify

**Files:** immutable Git tag, GitHub Release, NPM registry.

- [ ] Create and push annotated tag `v0.2.2` at the merged `main` commit.
- [ ] Wait for the tag-triggered GitHub Release workflow; verify assets, checksums, and provenance.
- [ ] Dispatch the NPM trusted-publishing workflow with `latest`; verify its success.
- [ ] Read NPM registry metadata and GitHub Release assets back from their live public endpoints.
